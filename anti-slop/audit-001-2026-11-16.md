# Audit Report 001: RKStride (Pulse Hybrid Athletics)

Tanggal: 2026-11-16
Mode: After (Mode 2)
Acuan Arah Visual: `DESIGN.md` (Dial: ENERGY 2 / RHYTHM 2 / MOTION 1)

Daftar temuan bernomor di bawah ini disusun berdasarkan prioritas aturan `antislop` (Hard Gate = HIGH, Purpose-Gate = MEDIUM, Quality Locks = LOW) dan mencakup evaluasi alur masuk pengguna (Login & Value Proposition), sistem tingkat pengalaman (Pemula, Menengah, Expert), kesiapan dokumentasi (`npm run doc:dev`), serta perencanaan Sprint Odoo.

---

## Temuan Prioritas Tinggi (Hard Gate = HIGH)

### 1. [HIGH] R-20, R-37, C-3: Ketiadaan Gerbang Awal (Landing Value Proposition & Login Atlet)
- **Alasan Satu Baris:** Aplikasi di `src/App.tsx` langsung merender dashboard teknis tanpa halaman pengenalan nilai produk (*value proposition*) dan tanpa gerbang masuk/login profil atlet, sehingga pengguna baru kehilangan konteks mengapa mereka harus menggunakan RKStride.
- **Lokasi:** `src/App.tsx` (baris 170-243), `src/components/OnboardingDisclaimerModal.tsx`.
- **Rencana Perbaikan:** Membangun gerbang awal terpadu yang menampilkan proposisi nilai RKStride secara jelas, alur Login / Pembuatan Akun Atlet Lokal (nama, identitas, pilih profil tersimpan), dan orientasi awal sebelum masuk ke dashboard utama.

### 2. [HIGH] R-06, R-31, C-1: Ketiadaan Sistem Adaptasi Bahasa Berdasarkan Tingkat Pengalaman (Pemula / Menengah / Expert)
- **Alasan Satu Baris:** Antarmuka memaksakan satu tingkat jargon akademik berat (*ACWR, Foster sRPE, Edwards TRIMP, Karvonen HRR, RIR*) kepada seluruh pengguna tanpa mode bahasa adaptif untuk Pemula, Menengah, dan Expert.
- **Lokasi:** `src/types/workout.ts`, `src/App.tsx`, `src/components/WorkloadAdvisorCard.tsx`, `src/components/WorkoutLogger.tsx`, `src/components/HeaderNavbar.tsx`.
- **Rencana Perbaikan:** Menambahkan sistem tingkat pengalaman (`beginner` / Pemula, `intermediate` / Menengah, `expert` / Expert) yang dapat dipilih saat login/onboarding maupun lewat pengalih cepat di Header, dengan kamus kosakata dinamis (contoh: Pemula melihat *"Status Keamanan Latihan"* & *"Skala Capek (1-10)"*, Menengah melihat *"Rasio Beban Mingguan (ACWR)"*, dan Expert melihat metrik fisiologi lengkap beserta pilihan formula *Coupled/Uncoupled/EWMA*).

### 3. [HIGH] R-24, R-26, C-2: Ketiadaan Portal Dokumentasi Interaktif (`npm run doc:dev`) dan Dokumen Sprint Odoo
- **Alasan Satu Baris:** `package.json` belum memiliki skrip `doc:dev` / `doc` dan belum tersedia pusat dokumentasi arsitektur, spesifikasi produk, kamus bahasa multi-tier, serta backlog Sprint Odoo yang terstruktur sebelum eksekusi sistem.
- **Lokasi:** `package.json` (baris 6-13), direktori `docs/`.
- **Rencana Perbaikan:** Membangun portal dokumentasi interaktif yang dapat dijalankan melalui `npm run doc:dev` (dan `npm run doc`) yang memuat: (a) Blueprint Produk & Value Proposition, (b) Spesifikasi UX Multi-Tier (Pemula/Menengah/Expert) & Alur Login, (c) Perencanaan **Sprint Odoo** lengkap (Epic, Sprint 1-4, User Stories, Story Points, Acceptance Criteria, dan struktur CSV/JSON siap impor ke Odoo Project), serta (d) Referensi Mesin Sains Olahraga.

### 4. [HIGH] R-17, R-23, R-38: Data Profil, Target Lomba, dan Draf Latihan Diasumsikan Tanpa Konfirmasi Pengguna
- **Alasan Satu Baris:** Sistem secara diam-diam menginisialisasi profil default (`Usia 28, 72 kg, 175 cm, RHR 52 bpm`), target lomba `Jakarta Half Marathon`, dan 2 gerakan latihan beban default tanpa input dari pengguna.
- **Lokasi:** `src/App.tsx` (baris 48-61), `src/lib/db/database.ts` (baris 91-100), `src/components/OnboardingProfileModal.tsx` (baris 20-31), `src/components/WorkoutLogger.tsx` (baris 85-112).
- **Rencana Perbaikan:** Menghapus seluruh data asumsi awal sehingga profil diambil dari input nyata saat Login/Registrasi awal, target lomba dimulai dari status kosong (`none`) hingga pengguna memilihnya, dan daftar latihan hari ini dimulai dari keadaan kosong yang jujur atau template yang dipilih pengguna secara eksplisit.

### 5. [HIGH] R-17, R-36, R-38: Parser File Smartwatch Menghasilkan Angka Fabrikasi Saat Gagal Membaca `.fit` / `.gpx` / `.tcx`
- **Alasan Satu Baris:** Fungsi `parseUniversalSmartwatchFile` membaca file biner `.fit` dan XML `.gpx/.tcx` sebagai teks CSV biasa lalu diam-diam mengembalikan angka palsu (`sleepHours = 7.5`, `restingHeartRate = 51`, `steps = 8800`) tanpa menampilkan status error.
- **Lokasi:** `src/lib/engine/smartwatch.ts` (baris 133-213), `src/components/SmartwatchSyncCard.tsx` (baris 56-68), `src/hooks/useWorkoutEngine.ts` (baris 232-253).
- **Rencana Perbaikan:** Menambahkan parser XML asli untuk `.gpx` dan `.tcx`, validasi header biner untuk `.fit`, meneruskan sesi lari yang terdeteksi (`workoutDetected`) ke log latihan, dan menampilkan pesan error jujur di UI bila format file tidak valid atau gagal dibaca (tanpa angka fallback palsu).

### 6. [HIGH] R-02: Penggunaan Karakter Em Dash pada Komponen UI dan Dokumentasi
- **Alasan Satu Baris:** Karakter *em dash* yang dilarang oleh R-02 masih ditemukan pada tampilan nilai RHR kosong di `WorkloadAdvisorCard.tsx` serta pada teks di `README.md`, `DESIGN.md`, `DELIVERY_GATE_REPORT.md`, dan `docs/science.md`.
- **Lokasi:** `src/components/WorkloadAdvisorCard.tsx` (baris 348), `DESIGN.md`, `README.md`, `docs/science.md`.
- **Rencana Perbaikan:** Mengganti seluruh karakter *em dash* dengan tanda baca standar (titik dua, koma, tanda kurung, atau teks eksplisit seperti `Belum diukur`).

### 7. [HIGH] R-26, R-36, C-2: Diskrepansi Rumus Beban UI vs Engine dan Fitur Mesin yang Terputus dari UI
- **Alasan Satu Baris:** Kartu latihan di `WorkoutLogger.tsx` menghitung skor dengan rumus berbeda dari `calculateStrengthLoad`, parameter `lastFastRunHoursAgo` masih di-hardcode `999` di `useWorkoutEngine.ts`, regex kaki melewatkan *Deadlift/Hip Thrust*, dan fungsi mesin (`estimate1RM`, `detectPersonalRecord`, `calculateWeeklyMuscleVolume`, `calculateKarvonenHeartRateZones`, metode ACWR `EWMA/Uncoupled`) belum ditampilkan di UI.
- **Lokasi:** `src/components/WorkoutLogger.tsx` (baris 469, 736-740, 825), `src/hooks/useWorkoutEngine.ts` (baris 100-108, 132, 137), `src/components/TrendsDashboardCard.tsx`.
- **Rencana Perbaikan:** Menyatukan kalkulasi beban latihan di UI dengan mesin `workload.ts`, menggunakan properti `isLegStrain` dari katalog untuk deteksi beban kaki, menghitung `lastFastRunHoursAgo` secara aktual dari riwayat lari, meneruskan riwayat 14-28 hari ke Z-Score kesiapan, serta menampilkan estimasi 1RM/PR, volume set otot mingguan, zona BPM Karvonen, dan pemilih model ACWR (pada mode Menengah/Expert).

- **Lokasi:** `src/App.tsx` (baris 280), `src/components/GeminiCoachWidget.tsx` (baris 393), `src/components/PostWorkoutDebriefModal.tsx` (baris 171, 191, 217), `src/components/WorkloadAdvisorCard.tsx` (baris 493).
- **Rencana Perbaikan:** Menghapus `borderLeft` dekoratif pada elemen statis dan menyisakannya hanya pada kartu yang merepresentasikan status fisiologis dinamis (*sweet spot*, *warning*, *danger*).
